# West Ashley Culinary Document Design Standard

## Purpose

Provide one consistent visual language for instructor-facing and student-facing West Ashley Culinary materials without forcing every artifact into the same template.

This standard applies to generated and substantially revised teaching guides, quick activities, station activities, round robins, scavenger hunts, student handouts, checklists, SOP delivery copies, observation forms, and similar working documents.

Recipes continue to follow the separate Recipe Bank / Standard Recipe Format requirements. Specialized spreadsheets, presentations, signs, and public-facing materials may require format-specific design decisions while preserving the same preference for clarity and restraint.

The normal finished working environment is Google Docs / district-approved Google Drive, even when a DOCX is generated first. Authoring choices should therefore favor formatting that converts cleanly to Google Docs.

## Governing Design Principle

**Formatting should clarify the work, not become part of the work.**

A West Ashley Culinary document should be easy to scan, calm on the page, and immediately usable in a classroom or working kitchen.

Do not print or create complexity simply because the source contains more information. Include what the intended reader needs for the task.

## Default Page Setup

- US Letter unless the artifact requires another size.
- **0.5-inch margins on all sides.**
- Portrait by default.
- Use landscape when the content genuinely works better horizontally, such as wide observation records, schedules, or operational tables.
- White background.
- No routine header or footer.
- Add page numbers only when a longer document benefits from them.
- Page count follows usability. Do not shrink content merely to force a one-page document, and do not stretch simple content into unnecessary pages.

## Typography

Use **Arial** as the default font because the final working environment is normally Google Docs and Arial is broadly supported, familiar, durable, and readable across systems.

Default hierarchy:

- **Document title:** 18 pt, bold, centered, black.
- **Course / activity subtitle:** 11 pt, centered, black. Italic may be used when it improves hierarchy.
- **Major section headings:** 12 pt, bold, `#366091`.
- **Body text:** 11 pt, black.
- **Supporting text:** 10 pt minimum and used sparingly.

Use bold for functional emphasis. Avoid excessive bolding, underlining, all-caps prose, or multiple competing text treatments.

Short functional headings may use all caps when that improves scanning, but ordinary prose should not.

## Color

The standard accent color is **`#366091`**.

Default use:

- Body text: black.
- Document title: black.
- Section headings: `#366091`.
- Background: white.

Do not introduce multiple decorative colors by default.

Color should help the reader navigate the page, not decorate it.

## Spacing and Density

- Use normal/single line spacing unless another setting clearly improves readability.
- Use paragraph spacing and whitespace to separate ideas rather than decorative bars or boxes.
- Leave a small visible space after bullets.
- Allow approximately 6–8 pt before major sections and 3–4 pt after headings as a working default.
- Keep related information together when possible.
- Do not crowd material at the top of a page while leaving unusable empty space below.
- Do not shrink body text to solve a layout problem.
- Handwritten student materials must provide genuine writing space.

The goal is balanced information density: enough information to do the work, with enough whitespace to find it quickly.

## Visual Restraint

Do not use these by default:

- colored banner bars;
- dashboard tiles;
- decorative sidebars;
- gradients;
- multiple accent colors;
- unnecessary icons;
- repeated shaded boxes;
- complex Word-specific text boxes or floating elements;
- tables used only to make a document appear organized.

Use a box, border, or callout only when the content genuinely needs separation or attention, such as an instructor checkpoint or safety stop.

Use tables when the information is naturally tabular, such as rotations, schedules, observation records, ingredient lists, or comparison information.

## Google Docs Compatibility

Because accepted working artifacts are commonly converted to Google Docs:

- prefer Arial and standard paragraph styles;
- use normal bullets and numbering;
- keep tables simple;
- avoid floating text boxes and Word-only layout tricks;
- avoid unnecessary section complexity;
- verify that conversion does not damage hierarchy, spacing, tables, or page breaks before treating an artifact as accepted.

The generated DOCX is often an authoring/delivery step. The accepted Google Drive copy is the normal reusable working artifact.

## One Visual Family, Different Structures

Consistency does **not** mean every document uses the same sections.

Choose the structure that fits the work while applying the same typography, color, margins, spacing, and restraint.

### Daily Teaching Guide / Instructor Lesson

The current Prototype D pilot uses this working family:

- Learning Target
- compact Knowledge / Skill / Professional Thinking
- Key Terms
- Before Class — Set Up
- Teach / Show
- Students Do
- Micro-Skills / If They Come Up
- Watch For
- If There Is Extra Time
- Clean Stop
- Notes for Next Time

Prototype D remains a pilot until separately adopted as the permanent DTG standard. This document standard does not itself finalize the DTG structure.

### Quick Instructor Activity

Use only the sections needed, commonly:

- Learning Target
- Set Up
- Teach / Explain
- Students Do
- Watch For / Check
- Finish / Clean Stop

### Student Activity

Common structure:

- Learning Target
- What You Are Doing
- Directions
- Work Area / Response Space
- When You Finish

### Stations / Round Robin

Common structure:

- Learning Target
- How This Works
- Rotation directions or starting point
- clearly labeled station/task sections
- Finish / Reset

When students rotate, directions should make the sequence clear. Use station numbers/labels and an instructor signal when the activity requires controlled rotation.

### Scavenger Hunt

Common structure:

- Purpose / Learning Target
- How It Works
- Hunt / Tasks
- Finish

### Checklist / SOP Delivery Copy

Common structure:

- Title
- brief purpose only when needed
- Opening / Set Up
- During / Work
- Closing / Reset

### Assessment / Observation Record

Use concise criteria and enough room to record evidence. Do not overload the page with explanatory text that belongs in the governing assessment standard.

## On-the-Fly Artifact Rule

When the instructor requests a printable, quick activity, station activity, scavenger hunt, checklist, lesson, or other working document without specifying design details, apply this standard automatically.

The instructor should not need to repeatedly request:

- readable fonts;
- less clutter;
- removal of decorative boxes;
- more whitespace;
- consistent margins;
- consistent color;
- larger writing space;
- Google Docs-friendly formatting.

Choose the appropriate document structure based on the task rather than forcing the content into the DTG template.

## Reader Test

Before delivering an artifact, ask:

1. Can the intended reader immediately tell what this document is for?
2. Can the reader quickly find what to do next?
3. Is the type comfortably readable in print and Google Docs?
4. Is there enough whitespace to scan or write without the page feeling empty?
5. Did formatting clarify the work rather than compete with it?
6. Could any visual element be removed without losing meaning? If yes, remove it.

For instructor-facing material, the practical test is:

**Can the instructor pick it up and know what needs to be prepared, taught, watched, and finished?**

For student-facing material, the practical test is:

**Can the student understand what to do without decoding the page?**

## Relationship to WACOS Sources

This standard governs presentation and usability. It does not override curriculum, safety, assessment, recipe, Bistro, or instructor-authority requirements.

Formatting-only changes to an accepted artifact do not create new WACOS policy. If redesign changes substantive content or operating expectations, use the WACOS Update Workflow.
